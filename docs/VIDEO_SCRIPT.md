### 0.4 图文分离的翻页节拍

这套页面的节奏是固定三段式，练两遍就能形成肌肉记忆：

```
文字页（讲逻辑，8~12 秒一个要点）
   └─ 收尾一句过渡语：「……请看屏幕。」
        └─ 点一下 → 截图页（不说话或只说一句定位语，停 15~20 秒）
             └─ 再点一下 → 下一个文字页（第一句必须接得上上一页的逻辑）
```

三条纪律：

1. **过渡语必须念出来，不能默默翻页。** 观众需要半秒的预期切换，否则会觉得画面"跳了一下"。
2. **截图页不逐行念内容。** 只指位置、只说结论。图上已经有的字，再念一遍是浪费这 18 秒。
3. **翻回文字页的第一句要接住上文。** 例如第 7 页开头"子集构造得到 52 个 DFA 状态"——它接的是第 6 页看完的 121 个状态。

常用过渡语（按场景选，不要每页都用同一句）：

| 场景 | 过渡语 |
| --- | --- |
| 从逻辑转到证据 | "下面看真实的构造结果，**请看屏幕**。" |
| 从结论转到细节 | "这一格在界面上长什么样，**请看屏幕**。" |
| 指向具体位置 | "**正如大家在图上看到的**，红框这一行……" |

### 第 5 页 · 任务一 · 把规则文本变成自动机

【时长】2:22–3:16（54 秒）　【类型】文字页

【画面】

- 页头副标题：输入一份 `.rules`：四类指令决定语言级行为，规则行决定单词集合。
- 顶部一排指令 chips：`@name` `@case-sensitive` `@ignore` `@comment`，右侧 `登记名 = 模式`，注“每条规则独立建片段，最后拼成一张图”。
- 两张设计决定卡：
  - **01 关键字不进自动机** —— 8 个关键字与标识符的正则在 DFA 里大量重合，建进去只白涨状态数；自动机只识别“看起来像标识符”的词，命中后再用关键字表做小写折叠重分类。卡底等宽行：`READ / read / Read 同落 108 号 KW_READ`。
  - **02 编码约定** —— 0 固定为 EOF，255 固定为 ERROR，语言包只分配 1..N；任何语言包生成的 `sample.lex` 都能被同一个读取器消费。卡底：`读取器不认语言，只认编码约定`。
- 中部 **THOMPSON 构造 / 五步拼成一张图** 流程链：`正则文本` → `递归下降 AST` → `Thompson 片段` → `偏移平移合并` → `空串校验`。
- 下方左框四行说明：① 每条规则独立建小 NFA ② 按当前状态数整体平移拼成总图 ③ 新建总起点，用 ε 连各条入口 ④ 从总起点求 ε 闭包，若含接受态说明能匹配空串 → 直接报错；第三行小字“不报的话，扫描时指针不前进，会死循环”。
- 下方右卡（TINY 实测）：`26 条规则` ｜ 8 条关键字不进自动机 ／ `18 条参与构造 → 121 个状态`。

【逐字稿】

任务一的核心是两段自动转换。一份 `.rules`，四类指令决定语言级行为，规则行决定单词集合。有两个设计决定值得说。

第一，关键字只登记编码、不进自动机。八个关键字和标识符的正则在 DFA 里大量重合，建进去只白涨状态数。做法是：自动机只识别“看起来像标识符”的词，命中后再用关键字表按小写折叠重分类。所以 TINY 不区分大小写时，READ、read、Read 都落到 108 号 KW_READ。

第二，编码 0 固定为 EOF、255 固定为 ERROR，语言包只分配 1 到 N。这条约定让任何语言的 `sample.lex` 都能被同一个读取器消费。

构造走 Thompson：每条规则独立建小 NFA，按当前状态数平移拼成总图，新建总起点用 ε 连各条入口。拼完还有一道校验——从总起点求 ε 闭包，闭包含接受态就说明有规则能匹配空串，直接报错。下面看真实的构造结果，**请看屏幕**。

【画面】

### 第 20 页 · 三件事决定了 IR 的形状

【时长】11:02–11:52（50 秒）　【类型】文字页

【画面】

- 页头副标题：四元式，四个字段全是字符串，空串表示这个字段不使用。
- 左侧三张编号卡：
  - **01 左值路径** `genLValue` 只取名字和下标、不读元素；右侧照常求值，最后按有无下标分派。示例 `([]=,1,0,arr)`，右注“与 `[]` 的（数组, 下标, 临时变量）互为镜像”。
  - **02 名字先行、定义后置** 进 `if/while/for` 先分配标签名；`jfalse` 发射时目标已是最终值。示例 `(label,,,L1)`，右注“缓冲只追加、不改写，不需要第二遍扫描”。
  - **03 操作符归一** TINY 的相等词素就是等号，不归一成 `==` 就分不清赋值与比较。示例 `(==,a,b,t15)`，右注“一元与二元运算符共用同一个映射表”。
- 右上代码块（深色，等宽）：`if f then g := 1 end` →
  `(jfalse,f,,L4)` ／ `(=,1,,g)` ／ `(label,,,L4)`（第三行蓝色）。
- 代码块下小卡：无 else 分支 → 只分配一个标签；跳转目标在发射时已确定，所以 IR 一遍成型。
- 右下：`四元式字段 op, arg1, arg2, result`，“编号 = 生成顺序 → 可逐条断言”。
- 底部：`t17 一定出现在 t16 之后，L4 是最后一个标签` —— 任何一处提前或延后求值，编号错位，断言立刻失败。

【逐字稿】

中间代码是四元式，四个字段全是字符串，空串表示不使用。有三件事决定了它的形状。

第一，赋值必须走左值路径。`variable := expression` 和普通表达式共用一个非终结符，按右值求值，`arr[0] = 1` 会被翻成“先读再赋值”，语义完全错。所以左侧单独走 `genLValue`：只取名字和下标、不读元素；右侧照常生成；最后按有无下标分派成 `=` 或 `[]=`。`[]=` 的字段和 `[]` 正好互为镜像。

第二，回填。困难在于跳转先出现、目标后出现。我用“名字先行、定义后置”：进 if、while、for 时先分配标签名，`jfalse` 发射的瞬间目标就是最终值，`label` 后面才发射。缓冲只追加、不改写，不需要第二遍扫描。

第三，操作符归一。TINY 的相等词素就是等号，不归一成 `==`，四元式里 `(=, a, b, t)` 是赋值还是比较就分不清。具体长什么样，**请看屏幕**。

补一个细节：139 条四元式是逐条断言的，不是“数量对上就算过”。临时变量和标签的编号本身就是生成顺序的证据——任何一处提前或延后求值，编号都会错位，断言立刻失败。

后续如果继续做，顺序应该是：符号表与类型检查、基本块划分与活跃分析、目标代码生成。
